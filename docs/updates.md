# GitHub 배포와 업데이트

공개 저장소: https://github.com/privatenote/HarborDrive

## 사용자 업데이트

앱은 기본적으로 시작할 때 GitHub의 최신 정식 릴리스 메타데이터를 한 번 확인합니다. 설정 메뉴에서 직접 확인하거나 시작 시 확인을 끌 수 있습니다. 초안·사전 릴리스는 안내하지 않으며, 해당 버전의 x64 설치 파일이 첨부된 릴리스만 업데이트로 표시합니다. API 오류나 요청 제한을 ‘최신 버전’으로 오인하지 않습니다.

업데이트는 다음 순서로 진행합니다.

1. 앱의 알림 또는 설정에서 GitHub 릴리스 페이지를 엽니다.
2. 새 Setup.exe를 다운로드합니다.
3. 파일을 사용하는 프로그램을 닫고 HarborDrive의 **모든 연결 해제 후 종료**를 선택합니다.
4. 새 설치 파일을 실행합니다. 연결 설정과 인증 정보, 캐시는 보존합니다.

현재 버전은 자동으로 설치 파일을 실행하거나 실행 중인 앱을 교체하지 않습니다. 설치 파일 코드 서명과 독립적인 서명 검증을 갖추기 전에는 릴리스 페이지를 통해 사용자가 설치하는 흐름을 유지합니다. GitHub의 공개 API에는 S3 인증 정보나 연결 설정을 전송하지 않습니다. 공개 저장소 조회이므로 사용자 GitHub 토큰도 앱에 필요하지 않습니다.

## 개발자 릴리스

1. `HarborDrive.App.csproj`의 버전을 올리고 `docs/releases/<version>.md`를 작성합니다.
2. 로컬 검사와 설치 검증을 수행합니다.
3. 변경 사항을 커밋·push하고 일치하는 버전 태그를 push합니다.

```powershell
git tag v0.1.3
git push origin main
git push origin v0.1.3
```

`.github/workflows/release.yml`이 Windows x64에서 검사 → 통합 설치 파일 빌드 → GitHub Release와 SHA256 첨부를 수행합니다. CI는 저장소의 `GITHUB_TOKEN`을 사용하므로 개발 PC에 별도 GitHub API 토큰을 보관할 필요가 없습니다. Git push는 등록된 SSH 키로 할 수 있습니다.

GitHub Actions는 기본·업데이트 검사를 실행합니다. 실제 WinFsp 마운트와 관리자 설치·제거 검사는 로컬 전용 시험 환경에서 따로 수행합니다. 실패한 릴리스를 고칠 때는 이미 공개한 버전의 설치 파일을 임의 교체하기보다 새 패치 버전과 태그를 만드세요.
