# 검증 기록 — 2026-11-05 (Asia/Seoul)

환경: Parallels Windows 11 Pro 25H2, ARM64. .NET SDK 10.0.403, rclone 1.75.2 ARM64 (`cmount` 포함), WinFsp 2.1.25156.

## 자동 검증

`scripts/test.ps1 -Integration`의 33개 검사가 통과했습니다. 사용자 AWS 계정과 S3 데이터는 사용하지 않았습니다. 임시 로컬 `rclone serve s3` 서버에 Signature V4로 접근하고 실제 WinFsp 네트워크 드라이브를 만들었습니다.

| 범위 | 검증 내용 |
| --- | --- |
| 설정 | 상대 경로·잘못된 ID·시스템 드라이브·URL 내 인증 정보·캐시 범위 거절 |
| 저장소 | DPAPI 왕복, 인증 정보 평문 미저장, 한글 설정 왕복, 손상 설정 보존 |
| 제어 채널 | 인증 정보 명령줄 미사용, 오류 메시지에서 키 제거, RC 비인증 제어 요청 거절 |

| 무결성 | 8MiB 난수 파일을 드라이브로 저장한 뒤 서버 원본과 SHA256 비교 |

| 강제 종료 | 전송 대기 중 엔진 강제 종료 후 앱 재실행 복구, 실행 중 감독자의 자동 엔진 재시작과 업로드 복구 |

반복 시험에서 오프라인 파일 접근이 만료된 디렉터리 메타데이터에 영향을 받는 것을 확인했습니다. 디렉터리 캐시는 기본 5분을 사용하며, 오프라인 검사는 파일/디렉터리를 먼저 읽어 캐시를 준비한 조건입니다. 처음 여는 파일과 만료된 경로가 오프라인에서도 작동한다는 보증은 하지 않습니다.

초기 시험 중 실패한 데이터도 `.devdata`에 보존했습니다. 마지막 통과 시험 데이터: `.devdata/test-852dd5822ecf44c39c446c9f081dec08`.

## 수동 확인과 남은 범위

Windows UI에서 첫 실행 화면, 연결 설정 다이얼로그, 추가 연결을 설정 메뉴 안에 두는 구성을 확인했습니다. 작은 화면에서 설정 창의 제목/버튼이 가려지지 않도록 높이와 스크롤을 조정했습니다.

최종 self-contained ARM64 패키지를 같은 테스트 S3 서버에 연결하여 드라이브 문자, 연결 상태, 캐시 용량, 대기 파일명·용량·시도 횟수가 실제로 표시되는 것을 확인했습니다. UI 시험용 파일은 서버 저장 내용도 확인했습니다.

창 닫기로 트레이에 숨긴 뒤 같은 EXE를 다시 실행하면 기존 창이 복원되고 rclone 프로세스 수가 증가하지 않는 것도 확인했습니다. 시험용 연결은 정상 해제하고 로컬 테스트 서버를 종료했습니다.

다음은 아직 검증하지 않았습니다: 실제 AWS S3 계정·IAM·SSE-KMS·STS 만료·대규모 multipart, Windows 강제 재부팅/전원 차단, 물리 디스크 부족, 다른 PC와의 동시 작성, x64 하드웨어, 백신/기업 정책별 설치 환경. 이 portable 초기 버전에는 코드 서명과 자동 업데이트가 없습니다.
