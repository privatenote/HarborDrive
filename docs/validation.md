# 검증 기록 — 2026-11-05 (Asia/Seoul)

환경: Parallels Windows 11 Pro 25H2, ARM64. .NET SDK 10.0.403, rclone 1.75.2 ARM64 (`cmount` 포함), WinFsp 2.1.25156.

## 자동 검증

`scripts/test.ps1 -Integration`의 33개 검사가 통과했습니다. 사용자 AWS 계정과 S3 데이터는 사용하지 않았습니다. 임시 로컬 `rclone serve s3` 서버에 Signature V4로 접근하고 실제 WinFsp 네트워크 드라이브를 만들었습니다.

초기 시험 중 실패한 데이터도 `.devdata`에 보존했습니다. 마지막 통과 시험 데이터: `.devdata/test-852dd5822ecf44c39c446c9f081dec08`.

## 수동 확인과 남은 범위

Windows UI에서 첫 실행 화면, 연결 설정 다이얼로그, 추가 연결을 설정 메뉴 안에 두는 구성을 확인했습니다. 작은 화면에서 설정 창의 제목/버튼이 가려지지 않도록 높이와 스크롤을 조정했습니다.

최종 self-contained ARM64 패키지를 같은 테스트 S3 서버에 연결하여 드라이브 문자, 연결 상태, 캐시 용량, 대기 파일명·용량·시도 횟수가 실제로 표시되는 것을 확인했습니다. UI 시험용 파일은 서버 저장 내용도 확인했습니다.

창 닫기로 트레이에 숨긴 뒤 같은 EXE를 다시 실행하면 기존 창이 복원되고 rclone 프로세스 수가 증가하지 않는 것도 확인했습니다. 시험용 연결은 정상 해제하고 로컬 테스트 서버를 종료했습니다.

다음은 아직 검증하지 않았습니다: 실제 AWS S3 계정·IAM·SSE-KMS·STS 만료·대규모 multipart, Windows 강제 재부팅/전원 차단, 물리 디스크 부족, 다른 PC와의 동시 작성, x64 하드웨어, 백신/기업 정책별 설치 환경. 이 portable 초기 버전에는 코드 서명과 자동 업데이트가 없습니다.

## 0.1.1 — x64 통합 설치 파일

- `HarborDrive.exe`, `coreclr.dll`, `rclone.exe`, `HarborDrive-0.1.1-x64-Setup.exe`의 PE Machine이 모두 `0x8664`(x86-64)인 것을 확인했습니다.
- ARM64 SDK에서 x64 런타임과 x64 rclone을 선택하여 교차 빌드했습니다. x64 구성요소가 ARM64 구성요소로 덮어써지지 않는지 패키지 단계에서 검사합니다.
- x64 self-contained 테스트 프로세스로 기본·통합 33개 검사를 통과했습니다. 실제 S3 호환 서버와 WinFsp x64 DLL을 사용했습니다. 결과: `.devdata/test-6ba36375e9be46da973bd2c9dc85e209`.
- 이 시험은 Windows ARM64의 x64 에뮬레이션입니다. Intel / AMD 물리 PC의 네이티브 실행 시험은 남아 있습니다.
- Inno Setup 7.1.1로 x64 설치·제거 프로그램을 컴파일했습니다. .NET·rclone·공식 WinFsp MSI를 내장하며 인터넷 다운로드 코드는 설치 프로그램에 없습니다.
- 실행 중 프로세스 보호, WinFsp 재사용, 재시작 필요 코드, 사용자 캐시 보존과 시작 항목 정리 분기가 포함되어 있습니다.
- 첫 관리자 설치·재설치·제거 검사에서 시작 항목 처리 문제를 발견했습니다. 최종 수정과 0.1.2 검증 결과는 아래에 기록합니다. 검증 스크립트는 `scripts/test-installer.ps1`이며 별도 임시 설치 경로를 사용합니다.
- 앱과 통합 설치 파일은 코드 서명되지 않았습니다. WinFsp 공급자 MSI의 서명과 고정 SHA256은 검증했습니다.

## 0.1.2 — 아이콘과 GitHub 업데이트 감지

- 앱 EXE·WPF 창·설치 프로그램과 트레이 아이콘을 직접 제작한 리소스로 교체했습니다. 연결 해제·연결·전송·오류의 네 가지 트레이 상태를 제공합니다. 16~256px ICO 프레임을 포함합니다.
- 실제 self-contained x64 앱의 `--smoke-test`가 창·트레이 리소스를 로드하고 종료 코드 0으로 완료했습니다. 이 검사는 빈 설정을 사용하고 S3를 연결하지 않습니다.
- 기본·업데이트 단위 검사 23개를 통과했습니다. 업데이트 검사는 버전 정규화, 같은 버전, 새 버전, 첨부 파일 누락, 정식 배포 없음, 사전 릴리스, API 실패를 다룹니다.
- 시작 항목 검증 하네스의 레지스트리 키 재생성 코드를 제거했습니다. 현재는 HarborDrive 값 하나만 수정하고 원래 값과 다른 시작 항목을 보존합니다. 제거 프로그램은 32·64비트 보기에서 설치 경로가 정확히 일치하는 값만 삭제합니다.
- 수정된 0.1.2 설치·재설치·제거의 관리자 검사 **20개가 통과했습니다.** 결과: `.devdata/installer-2c91285b4c664bcba844b969b0730671`. 설치·제거 등록, x64 바이너리, 실행 중 앱/엔진 보호, 창·트레이 리소스, 사용자 캐시 보존, 공유 WinFsp 보존과 시작 항목 정리를 확인했습니다.
- 앱이 저장하는 실행 경로의 따옴표를 제거 프로그램에서도 항상 동일하게 비교하도록 수정했습니다. 공백이 없는 임시 설치 경로에서도 HarborDrive 시작 값 하나만 정확히 삭제되는 것을 로그로 확인했습니다.
- GitHub의 네이티브 Windows x64 러너에서도 기본·업데이트 검사 23개, 앱 빌드, 창·트레이 아이콘 리소스 실행 검사를 통과했습니다. [실행 기록](https://github.com/privatenote/HarborDrive/actions/runs/42045600958).
